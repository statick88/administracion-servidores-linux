UNIDAD III: Scripting y Automatización con Bash

Objetivos de la Unidad

Al finalizar esta unidad, serás capaz de:

  • Escribir scripts Bash robustos (shebang, set -euo pipefail, funciones, validación de args).
  • Aplicar FHS para decidir dónde guardar scripts, logs, backups y datos de aplicación.
  • Gestionar permisos y ACLs en scripts y directorios de operación.
  • Crear scripts de backup rotativos (tar + gzip/zstd, retención, verificación de integridad).
  • Configurar logging estructurado (syslog/journald, rotación con logrotate).
  • Automatizar con cron y systemd timers (preferidos sobre cron en systemd).

1. Fundamentos de Scripting Bash Profesional

1.1 Estructura mínima obligatoria

Todo script profesional debe tener esta estructura base:

BASH
#!/usr/bin/env bash                                                      
# -*- coding: utf-8 -*-                                                 
# Script: backup-app.sh
# Descripción: Backup rotativo de /var/www/app a /mnt/backups/app
# Autor: Tu Nombre <tu@email.com>

set -euo pipefail                                                        
IFS=$'\n\t'                                                              

# --- Variables globales ---
readonly SCRIPT_NAME="$(basename "${BASH_SOURCE[0]}")"                   
readonly BACKUP_SRC="/var/www/app"
readonly BACKUP_DST="/mnt/backups/app"

# --- Funciones ---
log() {
    local level="$1"; shift
    local timestamp
    timestamp="$(date '+%Y-%m-%d %H:%M:%S')"
    echo "[$timestamp] [$level] $*"
}

die() { log "ERROR" "$*"; exit 1; }                                      

# --- Validación ---
[[ -d "$BACKUP_SRC" ]] || die "Origen no existe: $BACKUP_SRC"           
command -v tar >/dev/null || die "tar no instalado"                      

# --- Lógica principal ---
main() {
    local timestamp
    timestamp="$(date '+%Y%m%d-%H%M%S')"
    local archive="${BACKUP_DST}/app-${timestamp}.tar.zst"

    info "Iniciando backup..."
    tar --create --zstd -f "$archive" -C "$(dirname "$BACKUP_SRC")" "$(basename "$BACKUP_SRC")" \
        || die "Falló tar"                                               
    info "Backup completado: $archive"
}

main "$@"
  1. #!/usr/bin/env bash: Shebang portable — busca bash en $PATH
  2. # -*- coding: utf-8 -*-: Declara codificación del archivo
  3. set -euo pipefail: -e sale en error, -u variable no seteada, -o pipefail falla en pipe
  4. IFS=$'\n\t': Evita bugs con word splitting
  5. SCRIPT_NAME: Nombre del archivo sin path
  6. die(): Función de error que loguea y sale con código 1
  7. [[ -d ]]: Valida que el directorio existe
  8. command -v tar: Verifica que tar está instalado
  9. || die "Falló tar": Si tar falla, ejecuta die
  10. main "$@": Patrón estándar — lógica en main
Tip✅ Checklist de script robusto (Abacom Standard)

1.2 Variables y arrays

BASH
# Arrays (índice 0)
declare -a SERVICES=(nginx postgresql redis)                             
declare -A PORTS=( [nginx]=80 [postgresql]=5432 [redis]=6379 )           

# Iterar array
for svc in "${SERVICES[@]}"; do                                          
    systemctl is-active --quiet "$svc" || echo "$svc no activo"
done

# Default con expansión de parámetros
: "${BACKUP_DST:=/mnt/backups}"
  1. declare -a: Declara array indexado (numérico)
  2. declare -A: Declara array asociativo (mapa key→value)
  3. ${SERVICES[@]}: Expande todos los elementos del array
  4. ${VAR:=default}: Asigna default si la variable no está seteada

1.3 Manejo de errores y limpieza (traps)

BASH
cleanup() {
    local exit_code=$?                                                   
    [[ -n "${TMPDIR:-}" && -d "$TMPDIR" ]] && rm -rf "$TMPDIR"          
    exit $exit_code                                                      
}
trap cleanup EXIT INT TERM                                              

# Crear temp dir seguro
TMPDIR="$(mktemp -d)"                                                    
[[ -d "$TMPDIR" ]] || die "No se pudo crear directorio temporal"
  1. $?: Captura el código de salida del último comando ejecutado
  2. Validación ${TMPDIR:-}: Verifica que no está vacío antes de borrar
  3. exit $exit_code: Mantiene el código de salida original
  4. trap ... EXIT INT TERM: Ejecuta cleanup al salir (normal, interrupción, terminación)
  5. mktemp -d: Crea directorio temporal único en /tmp

2. Sistema de Archivos FHS

2.1 Estructura de directorios en Linux

BASH
# Ver estructura FHS
tree -L 1 /                                                             

# Directorios más importantes para administradores
ls -la /etc      # Configuración del sistema                              
ls -la /var      # Logs, caché, datos en ejecución                        
ls -la /opt      # Software de terceros                                   
ls -la /home     # Directorios de usuarios
  1. tree -L 1 /: Muestra la estructura de directorios hasta nivel 1
  2. /etc: Archivos de configuración del sistema
  3. /var: Logs, caché, datos en ejecución
  4. /opt: Software de terceros
  5. /home: Directorios de usuarios

2.2 Dónde guardar qué

Tipo de archivo Directorio FHS Ejemplo
Scripts del sistema /usr/local/sbin /usr/local/sbin/backup.sh
Scripts de usuario ~/bin o ~/.local/bin ~/bin/myscript.sh
Logs de aplicación /var/log/app /var/log/app/access.log
Backups /mnt/backups o /var/backups /mnt/backups/app-20260728.tar.zst
Configuración /etc/app /etc/app/config.yaml
Datos temporales /tmp o /var/tmp /tmp/process.pid
Note📝 Nota sobre FHS

El sistema de archivos jerárquico (FHS) define dónde debe ir cada tipo de archivo. No pongas scripts en /tmp ni configuraciones en /home. Respeta la convención.

2.3 Permisos y ACLs

BASH
# Verificar permisos
ls -la /etc/shadow                                                        

# Cambiar propietario y grupo
sudo chown root:adm /var/log/app                                         

# Permisos para directorio de logs
sudo chmod 750 /var/log/app                                              

# Verificar ACLs
getfacl /var/log/app                                                     

# Agregar ACL para usuario específico
sudo setfacl -m u:deploy:rwx /var/log/app                               

# Agregar ACL por defecto para nuevos archivos
sudo setfacl -d -m g:adm:r /var/log/app
  1. ls -la: Muestra permisos, propietario, grupo y fecha
  2. chown root:adm: Cambia propietario a root y grupo a adm
  3. chmod 750: Owner rwx, Group r-x, Others —
  4. getfacl: Muestra las ACLs de un archivo/directorio
  5. setfacl -m: Modifica la ACL para un usuario específico
  6. setfacl -d: Establece ACL por defecto para archivos futuros
Warning⚠️ ACLs y Seguridad

Las ACLs son poderosas pero pueden crear confusión. Úsalas solo cuando chmod tradicional no alcance. Siempre documenta qué ACLs has configurado.

3. Script de Backup Rotativo

3.1 Conceptos clave

  • Backup rotativo: Creas backups con timestamp y eliminas los viejos automáticamente
  • Retención: Cuántos días mantienes los backups (ej: 7 días)
  • Compresión: zstd (rápido) o gzip (compatibilidad)
  • Verificación: Siempre verifica que el backup se creó correctamente

3.2 Script de backup simplificado

BASH
#!/usr/bin/env bash
set -euo pipefail

# --- Configuración ---
readonly BACKUP_SRC="/var/www/app"
readonly BACKUP_DST="/mnt/backups"
readonly RETENTION_DAYS=7
readonly TIMESTAMP="$(date '+%Y%m%d-%H%M%S')"
readonly ARCHIVE="${BACKUP_DST}/app-${TIMESTAMP}.tar.zst"

# --- Validaciones ---
[[ -d "$BACKUP_SRC" ]] || { echo "ERROR: Origen no existe"; exit 1; }
command -v tar >/dev/null || { echo "ERROR: tar no instalado"; exit 1; }

# --- Crear backup ---
echo "[$(date '+%Y-%m-%d %H:%M:%S')] Iniciando backup..."
mkdir -p "$BACKUP_DST"

tar --create --zstd -f "$ARCHIVE" \
    -C "$(dirname "$BACKUP_SRC")" "$(basename "$BACKUP_SRC")"           

# --- Verificar ---
[[ -s "$ARCHIVE" ]] || { echo "ERROR: Backup vacío o no creado"; exit 1; }  
echo "[$(date '+%Y-%m-%d %H:%M:%S')] Backup completado: $ARCHIVE"

# --- Limpiar viejos ---
find "$BACKUP_DST" -name 'app-*.tar.zst' -type f -mtime +"$RETENTION_DAYS" -delete  
echo "[$(date '+%Y-%m-%d %H:%M:%S')] Retención: borrados backups > ${RETENTION_DAYS} días"
  1. -C "$(dirname)": Cambia al directorio padre antes de empaquetar
  2. [[ -s ]]: Verifica que el archivo no está vacío
  3. -mtime +N: Archivos modificados hace más de N días
Tip💡 Prueba primero con –dry-run

Antes de ejecutar el backup real, prueba el comando tar sin -f para ver qué se va a comprimir:

BASH
tar --create --zstd -f /dev/null -C /var/www app --dry-run

3.3 Verificar integridad del backup

BASH
# Verificar que se puede extraer
tar --test -f "$ARCHIVE"                                                 

# Listar contenido del backup
tar --list -f "$ARCHIVE"                                                 

# Extraer solo un archivo específico
tar --extract -f "$ARCHIVE" --to-stdout app/config.yaml
  1. --test: Verifica que el archivo está intacto
  2. --list: Muestra el contenido del backup
  3. --extract --to-stdout: Extrae un archivo a stdout sin modificar el disco

4. Logging Estructurado

4.1 Syslog vs Journald

BASH
# Syslog (tradicional)
tail -f /var/log/syslog                                                  

# Journald (systemd)
journalctl -f                                                            

# Ver logs de un servicio específico
journalctl -u nginx --since "1 hour ago"                                 

# Exportar logs a archivo
journalctl -u nginx --since today > /tmp/nginx-logs.txt
  1. tail -f: Sigue los nuevos eventos en tiempo real
  2. journalctl -f: Sigue todos los eventos del sistema
  3. -u nginx: Filtra por servicio específico
  4. --since today: Filtra por fecha

4.2 Crear logs propios en scripts

BASH
# Función de logging simple
log() {
    local level="$1"; shift
    local timestamp
    timestamp="$(date '+%Y-%m-%d %H:%M:%S')"
    echo "[$timestamp] [$level] $*" >> /var/log/myscript.log              
}

# Uso
log "INFO" "Backup iniciado"
log "ERROR" "Falló la conexión"
  1. >>: Append al archivo de log (no sobreescribe)

4.3 Rotación de logs con logrotate

BASH
# Configurar rotación para /var/log/myscript.log
cat > /etc/logrotate.d/myscript << 'EOF'                                  
/var/log/myscript.log {
    daily                    # Rotar diariamente                          
    missingok                # No error si no existe                      
    rotate 7                 # Mantener 7 rotaciones                      
    compress                 # Comprimir con gzip                         
    delaycompress            # No comprimir la rotación más reciente      
    notifempty               # No rotar si está vacío                     
    create 0640 root adm     # Permisos del nuevo archivo                 
}
EOF

# Probar la configuración
logrotate -d /etc/logrotate.d/myscript                                    

# Forzar rotación manual
logrotate -f /etc/logrotate.d/myscript
  1. /etc/logrotate.d/: Directorio para configuraciones personalizadas
  2. daily: Rotación diaria
  3. missingok: No falla si el archivo no existe
  4. rotate 7: Mantiene 7 archivos rotados
  5. compress: Comprime con gzip
  6. delaycompress: No comprimir la rotación más reciente
  7. notifempty: No rotar archivos vacíos
  8. create 0640 root adm: Permisos del nuevo archivo
  9. logrotate -d: Modo debug (no ejecuta, solo muestra)
  10. logrotate -f: Forzar rotación manual

5. Automatización de Tareas

5.1 Systemd Timers (recomendado en systemd)

BASH
# Crear servicio
cat > /etc/systemd/system/backup.service << 'EOF'                         
[Unit]
Description=Backup rotativo de /var/www/app
After=network.target

[Service]
Type=oneshot                                                              
ExecStart=/usr/local/sbin/backup.sh                                      
User=root
StandardOutput=journal
StandardError=journal
EOF

# Crear timer
cat > /etc/systemd/system/backup.timer << 'EOF'                          
[Unit]
Description=Ejecutar backup diariamente

[Timer]
OnCalendar=*-*-* 02:00:00                                               
Persistent=true                                                           

[Install]
WantedBy=timers.target
EOF

# Habilitar y activar
sudo systemctl daemon-reload                                              
sudo systemctl enable --now backup.timer                                 
sudo systemctl list-timers | grep backup
  1. Type=oneshot: Ejecución única (no servicio persistente)
  2. ExecStart: Ruta al script que se ejecuta
  3. OnCalendar: Horario de ejecución (02:00 diario)
  4. Persistent=true: Si el sistema estaba apagado, ejecuta al encender
  5. daemon-reload: Recarga la configuración de systemd
  6. enable --now: Habilita e inmediatamente activa
  7. list-timers: Muestra todos los timers configurados
Tip💡 Systemd Timers vs Cron

Usa systemd timers cuando: - El sistema usa systemd (la mayoría de distros modernas) - Necesitas dependencias (ej: esperar a que suba la red) - Quieres logs centralizados en journald - Necesitas ejecución persistente después de apagón

Usa cron cuando: - Estás en un sistema sin systemd - Necesitas compatibilidad con sistemas antiguos - La tarea es muy simple

5.2 Cron (alternativa tradicional)

BASH
# Editar crontab del usuario actual
crontab -e                                                                

# Ver crontab actual
crontab -l                                                                

# Ejemplos de programación
0 2 * * * /usr/local/sbin/backup.sh                                      
*/5 * * * * /usr/local/sbin/check-services.sh                            
0 0 * * 0 /usr/local/sbin/weekly-cleanup.sh
  1. crontab -e: Edita el crontab del usuario actual
  2. crontab -l: Lista las tareas programadas
  3. 0 2 * * *: Ejecuta a las 2:00 AM diariamente
  4. */5 * * * *: Ejecuta cada 5 minutos
  5. 0 0 * * 0: Ejecuta cada domingo a medianoche
Note📝 Sintaxis de Cron 
┌───────────── minuto (0-59)
│ ┌──────────── hora (0-23)
│ │ ┌──────────── día del mes (1-31)
│ │ │ ┌──────────── mes (1-12)
│ │ │ │ ┌──────────── día de la semana (0-7, 0=7=domingo)
│ │ │ │ │
* * * * * comando

5.3 Ejemplo práctico: Monitoreo de servicios

BASH
#!/usr/bin/env bash
# check-services.sh — Verifica servicios críticos
set -euo pipefail

readonly SERVICES=(nginx postgresql redis)
readonly LOG_FILE="/var/log/service-check.log

log() {
    local timestamp
    timestamp="$(date '+%Y-%m-%d %H:%M:%S')"
    echo "[$timestamp] $*" | tee -a "$LOG_FILE"                          
}

for svc in "${SERVICES[@]}"; do
    if systemctl is-active --quiet "$svc"; then                           
        log "OK: $svc activo"
    else
        log "ALERTA: $svc no activo — reiniciando..."                    
        sudo systemctl restart "$svc"
    fi
done
  1. tee -a: Escribe a pantalla Y append al archivo de log
  2. systemctl is-active --quiet: Verifica si el servicio está activo
  3. ||: Si no está activo, ejecuta el reinicio
